# 实战配方：门诊收费 → 开票（ABC数字医疗云）

这份文档记录的是**在一台真实生产机器上跑了几百张票之后**固化的流程。
换电脑时按它走，不用重新摸索。

不是「官方推荐」，是「这样跑过、这样错过、这样修好的」。

---

## 一条命令

```bash
pip install -r requirements.txt
python invoice.py --dry-run      # 先确认区域对，不开票
python invoice.py                # 开票，一直开到最后一张
```

默认参数就是这套业务系统调好的：

| 参数 | 值 | 为什么是这个值 |
|---|---|---|
| `top_text` | `开票` | 工具栏按钮 |
| `popup_text` | `开票` | 弹窗里的确认按钮（文字一样）|
| `interval` | `2.0` 秒 | 给系统响应时间；低于 1.5 秒偶发点空 |
| `wait_limit` | `45` 秒 | 电子票据要联网取数据，实测最慢卡过 **70 秒** |
| `empty_text` | `暂无可开发票` + `暂无患者` | 见下面「没得开了的三种长相」 |
| `absent_means_empty` | `true` | 按钮消失也算开完 |

**`wait_limit` 别调小。** 早期用过 10 秒，把「联网慢」误判成「按钮没出现」，
白白放弃能开出来的票。

---

## 没得开了的三种长相

同一个系统，队列空了有三种完全不同的表现，都要认：

| 长相 | 例子 | 怎么处理 |
|---|---|---|
| 弹提示框 | `暂无可开发票` | 放进 `empty_text` |
| 列表空文案 | `暂无患者` | 也放进 `empty_text` |
| **按钮直接消失** | 工具栏上「开票」整个不见 | `absent_means_empty: true` |

**可靠性排序很重要：文字提示 > 按钮消失。**

按钮会因为列表刷新而**短暂空白**十几毫秒。曾经抢在那个瞬间宣布「队列已空」，
一秒后按钮又回来了——白停一次，还少开一张。所以现在的顺序是：
先查文字，查不到才等 1.5 秒重看按钮。

---

## 会中断批量的四种界面动作

这些不是插件的 bug，是**有人同时在用那台电脑**。四种都会让批量停下：

| 动作 | 现象 | 结果 |
|---|---|---|
| 拖动窗口 | 点击比识别晚一拍，落空 | 停下，不误点 |
| 最大化 / 还原 | 坐标全变，弹窗跑到区域外 | 停下，不误点 |
| 最小化 | 屏幕上什么都没有 | 停下，不误点 |
| 切到别的页面 | 按钮所在页面不在了 | 停下，不误点 |

**所以：跑批量的时候别动那个窗口。** 真要动，先让它停下。

停下之后：把界面切回开票页，再跑一次 `python invoice.py`——
它会重新校准区域，不复用旧坐标。

**窗口比屏幕宽怎么办：** 如果业务窗口被拖到屏幕外，弹窗右半截会被切掉，
「开票」按钮只剩几个像素宽。这时候请把窗口调窄一点或最大化，
让弹窗完整落在屏幕里——插件会照常停下，但那样才开得下去。

## 危险动作：同一个位置会换按钮

**这是这个任务里唯一会造成财务事故的地方。**

一张单开完票之后，同一个位置上的「开票￥17.88」会变成「**红冲**」。
红冲是冲销操作，点错了是真事故。

插件现在**每次按下鼠标之前都重新识别一次**目标文字：

```
拒绝点击 (1899,914): 那里现在是 '红冲', 已经不是 '开票'
```

认不出「开票」就不点，并把那一带实际写着什么报出来。
目标还在但位置跳超过 40px 也拒绝——那说明界面重构了。

**它的局限，说清楚：**

- 验证的是**文字**，不是**语义**。OCR 把「红冲」认成「开票」就拦不住。
- 直接按像素坐标点的 `screen_click` **不做验证**，要安全就别用它。

---

## 开不了票的记录

两类记录点了「开票」不会有反应，批量会停在那一条：

1. **已退费**的单（退费单不能开票）
2. **已经开过票**的单

表现是「点了『开票』但弹窗一直没出现」。这不是故障，是这条记录的状态不允许。

## 速度参考

同一台机器实测（1920×1080，DPI 125%）：

| 阶段 | 每张耗时 |
|---|---|
| 早期（无切前台、无闸门） | 4.0 ~ 5.0 秒 |
| 加切前台 | 7.0 ~ 8.4 秒 |
| 加按下前复检 | 8.0 ~ 10.0 秒 |
| **窄带复检 + 快节奏（现在）** | **6.8 ~ 7.2 秒** |

慢是**买安全**：切前台解决「后台窗口不响应点击」，复检解决「按钮中途换掉」。
单轮最长连续跑过 **108 张零失误**。

### 时间到底花在哪（用 --timing 看）

`python invoice.py --fast --timing` 会在每张后面打一行分解：

```
[2] 完成 上(1714,117) 下(1802,865) 6.8s  [定位1.6 等弹窗1.4 复检1.2 等关闭2.5]
```

| 阶段 | 耗时 | 是谁的时间 | 能不能省 |
|---|---|---|---|
| 定位 | 1.6 秒 | 插件 OCR 工具栏 | 已用窄带优化，还能省一点 |
| 等弹窗 | 1.4 秒 | 业务系统渲染弹窗 | 省不掉 |
| 复检 | 1.2 秒 | 插件 OCR 弹窗 | **不能省**（这是防红冲的那一步）|
| 等关闭 | 2.5 秒 | 业务系统联网取票据 | 省不掉 |

**规律：插件占 2.5~3 秒，业务系统占 4 秒以上。** 想再快只能改业务系统，
不该再挤复检——那一秒是买「不点红冲」的。

定位能省是因为它只是找按钮；复检省掉就等于回到「照旧坐标盲点」，
那正是会造成财务事故的写法。

## 排错顺序

停下来的时候，按这个顺序查，别乱点：

1. **看停止原因那句话**，它说的是哪一种：
   - `出现 '暂无可开发票'` → 正常，活干完了
   - `工具栏上已经没有 '开票'` → 队列空了，或者界面切走了
   - `拒绝点击...已经是 '红冲'` → 闸门起作用了，**别强行点**
   - `点了 '开票' 但...一直没出现` → 这条记录开不了，或者窗口在动
2. **窗口还在原位吗**（用 `screen_windows` 看矩形）
3. **还在那个页面吗**（页面上还有「开票」按钮吗）
4. **没得开了吗**（`暂无患者` / `暂无可开发票`）

第 2、3 步任一不满足，先把界面弄回去，再 `python invoice.py`。

## 打印：电子发票 → A5 纸

### 二维码地址不能直接当 PDF 用

扫码枪扫出来的 `https://abcyun.cn/s/xxxx` 返回的是 **HTML（前端 JS 应用，约 39 KB）**，
不是 PDF。真正跳到发票的那一步是在 JS 里做的，所以抓这个地址拿不到发票。

但 `http://einvoice.jsczt.cn/d/<id>` **直接返回 `application/pdf`**——
只要知道 id，下载打印完全不依赖浏览器。

### 页面尺寸不是 A5（这是坑的根源）

实测这张发票 PDF 共 3 页，页面尺寸分别是：

```
190 × 127 mm
190 × 281 mm
190 × 127 mm
A5 标准是 148 × 210 mm
```

**190 mm 宽塞进 148 mm 的纸里，必须缩到约 78%。**

### 别用 Foxit：它不听纸张设置

实测两次，结论明确：

| 做法 | 结果 |
|---|---|
| 打印机默认纸张设 A5 + `Foxit /t` | **无效**。打出来仍是 A4 排版，A5 纸两边被裁掉 |
| `SumatraPDF -print-settings "paper=A5,fit"` | **正确**，A5 出纸内容完整 |

Foxit 的 `/t` 用的是它自己记住的纸张（A4），会把打印机默认值覆盖掉。
**只有把纸张和缩放写进打印任务里才可控。**

安装（工具本身不在仓库里，体积大且会更新）：

```bash
winget install -e --id SumatraPDF.SumatraPDF
```

### 一条命令

```bash
python tools/print_invoice.py --once <发票地址>          # 下载并 A5 打印
python tools/print_invoice.py --once <地址> --dry-run    # 只下载, 不打印
python tools/print_invoice.py --from-screen              # 从浏览器地址栏 OCR 取地址
python tools/print_invoice.py                            # 扫码枪逐行扫（读标准输入）
```

### 一个重要的校验

`download()` 会检查返回内容是不是以 `%PDF` 开头，不是就报错退出。

这不是洁癖：从**地址栏 OCR 出来**的 URL 有识别错的风险
（`0/O`、`1/l` 这类），打错一张发票比不打印麻烦得多。
宁可在下载这一步失败，也不要拿一个能打开但内容不对的页面去打印。

### 打印：盯 Downloads

发票 PDF 会出现在 `~/Downloads`，文件名就是发票 id：

```
C:\Users\Administrator\Downloads\4730125ecbb16ca1671.pdf   227287 字节
```

内容和 `http://einvoice.jsczt.cn/d/4730125ecbb16ca1671` 下载的**字节完全一致**。

**这个文件是人工下载的，不是系统自动落的。**
所以下面这个模式只省掉「打印」那一步，「下载」仍然要人点一下。

```bash
python tools/print_invoice.py --watch              # 盯着 Downloads, 出现新发票就 A5 打印
python tools/print_invoice.py --watch --dry-run    # 只看不动纸
python tools/print_invoice.py --watch --after-print move   # 打完移到 Downloads/_printed
```

**第一次运行不会把历史文件全打一遍**：它把现有文件登记进
`%LOCALAPPDATA%\dsh-screen-kit\printed.json`，只处理之后新增的。
要补打历史文件加 `--print-existing`。

文件名规则是 `^[0-9a-f]{17,24}\.pdf$`，下限 17 是为了排除 Downloads 里
常见的 16 位纯数字临时文件（实测混进来一个 `1217322539213690.pdf`）——
**打错一张发票比漏打麻烦得多**，所以宁可规则紧一点。

### 想连下载也省掉：读浏览器地址栏

如果扫码后浏览器会自己跳到 PDF，地址栏里就是最终地址，
用屏幕 OCR 读出来即可，不用人下载：

```bash
python tools/print_invoice.py --from-screen          # 读地址栏 -> 下载 -> A5 打印
python tools/print_invoice.py --from-screen --dry-run
```

OCR 读 URL 有认错字符的风险（`0/O`、`1/l`），所以下载时强制校验返回值以 `%PDF` 开头，
不对就停 —— 宁可不打，也不要打错一张。

## 自助打印机（扫码即出纸）

一个窗口，扫码枪扫一下，A5 打一张。

双击仓库根目录的 **`发票自助打印.bat`**，出现：

```
        请扫描发票二维码
  [ ____________________________________ ]

  就绪。扫码枪扫一下即可，按 Esc 退出。
```

把光标留在输入框里，扫一张，它会自己走完：

```
  收到: https://abcyun.cn/s/2yHIJ5X
  打开页面 ...
  发票地址: http://einvoice.jsczt.cn/d/4730125ecbb16ce5f58
  200 KB, 3 页
  SumatraPDF (paper=A5,fit)
  ✅ 打印完成
```

### 它内部做了什么

1. 扫码枪就是个键盘，把短链敲进输入框 + 回车
2. 用 Chrome 打开短链 —— 短链是 JS 应用，发票地址要 JS 跑完才出现在页面上
3. OCR 那个窗口，把 `einvoice.jsczt.cn/d/<id>` 读出来
4. 关掉那个浏览器窗口（不留残页）
5. 直接下载 PDF（**不经过浏览器下载，不需要人工保存**）
6. A5 + 适合页面，打印

### 为什么不开无头浏览器

试过 `chrome --headless --dump-dom`：那个页面加载了 **socket.io 长连接**，
`--dump-dom` 永远等不到「加载完成」，实测 60 秒超时、拿不到 DOM。
所以只能开一个真实窗口让 JS 跑，再用 OCR 读。

### 三道防错

1. **十六进制归一化**：发票 id 是十六进制，字母只可能是 `a-f`。
   OCR 常把 `0` 认成 `O`、`1` 认成 `l/I`、`5` 认成 `S`、`8` 认成 `B`，
   这些按固定映射掰回来。
2. **下载校验 `%PDF`**：返回的不是 PDF 就报错停下，**绝不打印**。
3. **打错一张比漏打严重** —— 所以宁可失败退出，也不猜。

### 实测记录

| 扫码内容 | 解出的发票地址 | 结果 |
|---|---|---|
| `abcyun.cn/s/2yHIJ5X` | `.../d/4730125ecbb16ce5f58` | 与 Downloads 里同名文件一致 ✅ |
| `abcyun.cn/s/lp9WyF0` | `.../d/4730125ecbb16c9c032` | 与 Downloads 里同名文件一致 ✅ |

### 打印机默认纸张

靠 `-print-settings paper=A5` 按任务指定就够了，**不需要改打印机默认值**。
（中途改过一次 A5，验证完已经改回 A4，避免影响这台机器上的其他打印。）

## 窗口太窄会折行（实测数据）

把业务窗口拖窄到 **938 像素**时，工具栏会折成两行：

```
已收费退费      (1549, 90)
追溯开票打印    (1674, 93)      ← 被压成一段
码             (1683, 114)     ← 换行了
费             (1371, 132)     ← 换行了
```

这时候点「开票」**什么都不会发生**，而且弹窗根本不出现。
原因不是插件找不到按钮——它找到了，还点了——而是按钮被挤到别的位置，
OCR 算出的中心落在了按钮接缝上。

**解法：把窗口拉宽到工具栏不折行为止。不需要最大化。**

同一台机器实测：

| 窗口宽度 | 结果 |
|---|---|
| 938 px（拖窄） | 工具栏折行，点击落空，弹窗不出现 |
| **1248 px（拉宽，右边贴屏幕）** | **正常，一次开出** |
| 1938 px（最大化） | 正常 |

**1248 就够了，别最大化。** 最大化会把屏幕上的其他窗口整个盖住——
如果旁边还有窗口要看着（日志、控制台、聊天），最大化等于让人瞎了。
拉到刚好不折行的宽度最实用：这次是 `x=672, w=1248`，右边正好贴到 1920。

拉宽之后校准会自动算出新区域（1248 宽时是 `571,53,1000,160` + `752,715,1000,904`），
不需要手改任何东西。

校准失败时的提示现在会直接点出这两种可能：窗口太窄，或者这条记录不允许开票。
