# 实战配方：门诊收费 → 开票（ABC数字医疗云）

这份文档记录的是**在一台真实生产机器上跑了几百张票之后**固化的流程。
换电脑时按它走，不用重新摸索。

不是「官方推荐」，是「这样跑过、这样错过、这样修好的」。

---

## 一条命令

```bash
pip install -r requirements.txt
python invoice.py --dry-run      # 先确认区域对，不开票
python invoice.py                # 开票，一直开到最后一张
```

默认参数就是这套业务系统调好的：

| 参数 | 值 | 为什么是这个值 |
|---|---|---|
| `top_text` | `开票` | 工具栏按钮 |
| `popup_text` | `开票` | 弹窗里的确认按钮（文字一样）|
| `interval` | `2.0` 秒 | 给系统响应时间；低于 1.5 秒偶发点空 |
| `wait_limit` | `45` 秒 | 电子票据要联网取数据，实测最慢卡过 **70 秒** |
| `empty_text` | `暂无可开发票` + `暂无患者` | 见下面「没得开了的三种长相」 |
| `absent_means_empty` | `true` | 按钮消失也算开完 |

**`wait_limit` 别调小。** 早期用过 10 秒，把「联网慢」误判成「按钮没出现」，
白白放弃能开出来的票。

---

## 没得开了的三种长相

同一个系统，队列空了有三种完全不同的表现，都要认：

| 长相 | 例子 | 怎么处理 |
|---|---|---|
| 弹提示框 | `暂无可开发票` | 放进 `empty_text` |
| 列表空文案 | `暂无患者` | 也放进 `empty_text` |
| **按钮直接消失** | 工具栏上「开票」整个不见 | `absent_means_empty: true` |

**可靠性排序很重要：文字提示 > 按钮消失。**

按钮会因为列表刷新而**短暂空白**十几毫秒。曾经抢在那个瞬间宣布「队列已空」，
一秒后按钮又回来了——白停一次，还少开一张。所以现在的顺序是：
先查文字，查不到才等 1.5 秒重看按钮。

## 会中断批量的四种界面动作

这些不是插件的 bug，是**有人同时在用那台电脑**。四种都会让批量停下：

| 动作 | 现象 | 结果 |
|---|---|---|
| 拖动窗口 | 点击比识别晚一拍，落空 | 停下，不误点 |
| 最大化 / 还原 | 坐标全变，弹窗跑到区域外 | 停下，不误点 |
| 最小化 | 屏幕上什么都没有 | 停下，不误点 |
| 切到别的页面 | 按钮所在页面不在了 | 停下，不误点 |

**所以：跑批量的时候别动那个窗口。** 真要动，先让它停下。

停下之后：把界面切回开票页，再跑一次 `python invoice.py`——
它会重新校准区域，不复用旧坐标。

**窗口比屏幕宽怎么办：** 如果业务窗口被拖到屏幕外，弹窗右半截会被切掉，
「开票」按钮只剩几个像素宽。这时候请把窗口调窄一点或最大化，
让弹窗完整落在屏幕里——插件会照常停下，但那样才开得下去。

## 危险动作：同一个位置会换按钮

**这是这个任务里唯一会造成财务事故的地方。**

一张单开完票之后，同一个位置上的「开票￥17.88」会变成「**红冲**」。
红冲是冲销操作，点错了是真事故。

插件现在**每次按下鼠标之前都重新识别一次**目标文字：

```
拒绝点击 (1899,914): 那里现在是 '红冲', 已经不是 '开票'
```

认不出「开票」就不点，并把那一带实际写着什么报出来。
目标还在但位置跳超过 40px 也拒绝——那说明界面重构了。

**它的局限，说清楚：**

- 验证的是**文字**，不是**语义**。OCR 把「红冲」认成「开票」就拦不住。
- 直接按像素坐标点的 `screen_click` **不做验证**，要安全就别用它。

## 开不了票的记录

两类记录点了「开票」不会有反应，批量会停在那一条：

1. **已退费**的单（退费单不能开票）
2. **已经开过票**的单

表现是「点了『开票』但弹窗一直没出现」。这不是故障，是这条记录的状态不允许。

## 速度参考

同一台机器实测（1920×1080，DPI 125%）：

| 阶段 | 每张耗时 |
|---|---|
| 早期（无切前台、无闸门） | 4.0 ~ 5.0 秒 |
| 加切前台 | 7.0 ~ 8.4 秒 |
| 加按下前复检 | 8.0 ~ 10.0 秒 |

慢是**买安全**：切前台解决「后台窗口不响应点击」，复检解决「按钮中途换掉」。
单轮最长连续跑过 **108 张零失误**。

## 排错顺序

停下来的时候，按这个顺序查，别乱点：

1. **看停止原因那句话**，它说的是哪一种：
   - `出现 '暂无可开发票'` → 正常，活干完了
   - `工具栏上已经没有 '开票'` → 队列空了，或者界面切走了
   - `拒绝点击...已经是 '红冲'` → 闸门起作用了，**别强行点**
   - `点了 '开票' 但...一直没出现` → 这条记录开不了，或者窗口在动
2. **窗口还在原位吗**（用 `screen_windows` 看矩形）
3. **还在那个页面吗**（页面上还有「开票」按钮吗）
4. **没得开了吗**（`暂无患者` / `暂无可开发票`）

第 2、3 步任一不满足，先把界面弄回去，再 `python invoice.py`。

## 窗口太窄会折行（实测数据）

把业务窗口拖窄到 **938 像素**时，工具栏会折成两行：

```
已收费退费      (1549, 90)
追溯开票打印    (1674, 93)      ← 被压成一段
码             (1683, 114)     ← 换行了
费             (1371, 132)     ← 换行了
```

这时候点「开票」**什么都不会发生**，而且弹窗根本不出现。
原因不是插件找不到按钮——它找到了，还点了——而是按钮被挤到别的位置，
OCR 算出的中心落在了按钮接缝上。

**解法：把窗口拉宽或最大化。** 同一台机器实测：

| 窗口宽度 | 结果 |
|---|---|
| 938 px（拖窄） | 点击落空，弹窗不出现 |
| 1938 px（最大化） | 正常，一次开出 |

最大化之后校准会自动算出新的区域（这次是 `389,19,943,124` + `572,742,920,931`），
不需要手改任何东西。

校准失败时的提示现在会直接点出这两种可能：窗口太窄，或者这条记录不允许开票。
